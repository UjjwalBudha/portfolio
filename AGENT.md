# AGENT.md

Instructions for AI coding agents (Claude Code, Cursor, etc.) working in this repository.

## What this is

Ujwal Budha's personal portfolio and DevOps/Cloud blog, deployed at `https://ujwalbudha.com.np`, served through Cloudflare in front of a Vercel origin.

## Stack

- **Mostly static, with an Eleventy (11ty) build step for blog content.** `index.html`, `portfolio-details.html`, `404.html` at the root are plain HTML. Blog posts are split across two generations: 12 legacy posts are hand-written static HTML directly in `blogs/*.html`; new posts go through the pipeline — Markdown + front matter in `content/blogs/*.md`, rendered via `_includes/layouts/blog.njk`. Vercel runs `npx @11ty/eleventy` on every push (see `vercel.json`); the build output directory is `_site/` (gitignored, never commit it).
- **Styling:** Bootstrap 5 (`assets/vendor/bootstrap`) + custom `assets/css/style.css` (site-wide) and `assets/css/blog.css` (pipeline blog-post layout, extracted from what used to be a duplicated inline `<style>` block per post). Fonts: Open Sans (body), Raleway (nav/section titles + blog post body), Poppins (headings/buttons). No CSS custom properties exist yet — don't hardcode a new color/spacing value more than once, promote it to a `:root` var instead.
- **JS:** jQuery + vendor plugins (isotope, owl.carousel, venobox, waypoints, counterup), plus `assets/js/main.js` and `assets/js/navbar.js`. Keep new interactive behavior in that same jQuery style rather than introducing a framework.
- **Serverless functions:** `api/*.js` (Vercel functions), e.g. `api/cf-geoip.js` reads Cloudflare edge headers — see `CLOUDFLARE_GEOIP_POC.md` for what it validates and how to test it in production. Vercel auto-detects `/api` independently of the Eleventy build's `outputDirectory` — untouched by the build.
- **Forms:** `forms/contact.php` (PHP mail form, not a serverless function).
- **Tests:** Vitest + jsdom (`vitest.config.js`). Run with `npm test`. Test files live next to what they cover (e.g. `api/cf-geoip.spec.js`, `cf-test.spec.js`). Unrelated to the Eleventy build.
- **Sitemap:** generated by Eleventy (`sitemap.njk`) from the same blog-post collection that drives the homepage list — not a separate CI job anymore (the old `.github/workflows/update-sitemap.yml` Python-script Action was retired for this).

## Required reading before specific tasks

- **Before writing or editing any blog post:** read `BLOG_STANDARDS.md` in full — it now leads with "How to Write a New Post Now" (the Eleventy pipeline workflow) before the underlying SEO/meta/JSON-LD rules the pipeline generates for you.
- **Before any visual/layout/styling change:** the `web-design` skill (`.claude/skills/web-design/`) has this repo's concrete typography/color/spacing/accessibility rules.
- **Before touching the Cloudflare/geoip diagnostic page or API:** read `CLOUDFLARE_GEOIP_POC.md`.
- **Before changing `.eleventy.js`/`vercel.json`:** this is a production build-config change with no local dry-run on Vercel itself — test via a preview deployment (see Deployment below) before merging to `main`.

## Conventions

- No package manager for the static homepage/legacy pages — only blog content goes through the Eleventy build. Adding a new vendor library means vendoring the file(s) under `assets/vendor/`, not adding an npm/build dependency.
- Images should be converted to WebP where practical (see the two `*_webp.py` scripts) for performance — this is still a manual step for both legacy and pipeline posts.
- New blog posts go through `content/blogs/*.md` per `BLOG_STANDARDS.md` — the homepage list and `sitemap.xml` update automatically, don't hand-edit either.
- Author/contact identity across meta tags, JSON-LD, and forms is "Ujwal Budha" — keep it consistent.

## Testing

```bash
npm test        # vitest run, jsdom environment
npx @11ty/eleventy   # build the site into _site/ — do this before pushing a build-config change
```

`npm test` covers the `api/` serverless functions and the Cloudflare diagnostics logic; there is no test coverage for the static HTML/CSS itself — visual changes need manual browser verification (see the `web-design` skill's "definition of done"). Writing a normal blog post doesn't require running Eleventy locally — Vercel builds it on push.

## Deployment

Push to `main` deploys via Vercel (`vercel.json` runs `npx @11ty/eleventy`, output `_site/`); Cloudflare sits in front for proxying/geoip. A `stg` branch exists and gets its own Vercel Preview deployment — use it to verify build-config or blog-pipeline changes before merging to `main`, which is production.
